P2 매일 아침 민원 브리핑 봇

정해진 시각에 스스로 실행됩니다

왜 이게 필요한가

  • 1일차 자동화 덕분에 민원은 시트에 쌓이지만, 쌓이기만 함 — 매일 스크롤을 내려 건수를 세고 종류별로 눈대중하는 건 여전히 사람 몫
  • 세기·분류·요약은 기계가 더 잘함 — 사람이 할 일은 요약을 읽고 오늘 무엇을 먼저 할지 정하는 것뿐
  • 해결: 매일 아침 9시 아무도 시키지 않아도 시트를 열어 전체 건수와 종류별 건수를 세고, 급해 보이는 건을 짚어 메일+텔레그램으로 보냄
새로 배우는 것 두 가지

① 정해진 시각에 혼자 실행되기(스케줄 트리거) — 지금까지는 버튼을 누르거나 폼을 제출해야 움직였습니다.

② 여러 건을 한 번에 합쳐서 다루기(Aggregate) — 흩어진 건을 하나로 묶어야 AI가 한 번만 실행됩니다.

이번 시간에 만들 것

매일 아침 9시가 되면 스스로 실행되어 1일차에 만든 구글 시트의 민원 기록을 전부 읽고, AI가 일일 브리핑을 작성해 메일과 텔레그램 두 곳에 동시에 보내는 워크플로우를 만듭니다.

1일차 시트에 민원이 몇 건 쌓여 있어야 함 비어 있다면 1일차 워크플로우를 두세 번 실행하거나 시트에 직접 몇 줄 입력하세요.

앞 네 노드는 일직선, 마지막에만 메일·텔레그램 두 갈래로 나뉨.

따라하기

  1. 새 워크플로우 만들기 이름을 P2 매일 아침 민원 브리핑 봇으로
  2. 시각 트리거 추가하기 + → Schedule Trigger

    Trigger Interval = Days(기본값)
    Days Between Triggers = 1(기본값)
    Trigger at Hour = 9am으로 변경
    Trigger at Minute = 0(기본값)

  3. 구글 시트 읽어오기 + → Google Sheets → Get Row(s) in Sheet(읽기)

    자격증명 1일차 재사용 → Document=민원 시트, Sheet=시트1

  4. 여러 줄을 한 덩어리로 합치기 + → Aggregate → All Item Data (Into a Single List)
    이 노드를 빼면 브리핑이 수십 통 날아옴 시트 읽기는 한 줄씩 따로 내보냄 → 이 노드가 흩어진 건들을 하나로 묶어야 AI가 한 번만 실행됨
  5. AI 브리핑 노드 추가하기 + → Basic LLM Chain → Source for Prompt = Define below 
    당신은 시청의 업무 비서입니다.
아래는 오늘까지 접수된 민원 목록입니다.
담당 공무원이 아침에 한눈에 볼 수 있도록 간단한 '일일 민원 브리핑'을 작성해 주세요.

[규칙]
- 전체 건수를 먼저 알려줍니다.
- 종류별 건수를 정리합니다.
- 특히 시급해 보이는 민원 1~2건을 짚어줍니다.
- 5~8줄로 간결하게 작성합니다.

[민원 목록]
{{ JSON.stringify($json.data) }}
  6. Gemini 모델 붙이고 모델 이름 고르기 아래쪽 + → Google Gemini Chat Model → 자격증명 재사용 → models/gemini-2.5-flash 직접 선택
    모델은 매번 직접 골라야 함 — preview 모델은 예고 없이 사라질 수 있음
  7. 브리핑 메일 보내기 + → Gmail(1일차 자격증명)

    To = 본인 이메일(글자 그대로)
    Subject = 표현식, [일일 민원 브리핑] {{ $now.toFormat('yyyy-MM-dd') }}
    Email Type = Text
    Message = 표현식, {{ $json.text }}

  8. 텔레그램에도 같이 보내기 AI 브리핑 작성 노드 오른쪽에서 다시 + → Telegram
    메일 노드 뒤에 붙이면 안 됨 — Gmail을 지나면 브리핑 글이 사라짐. 두 노드 모두 AI 브리핑 작성에서 각각 직접 연결

    P1 텔레그램 자격증명 재사용, Chat ID = 본인 숫자, Text 표현식:

    📋 일일 민원 브리핑

{{ $json.text }}
  9. 노드 이름 정리하기

    매일 아침 9시 · 민원 현황 읽기 · 한 건으로 합치기 · AI 브리핑 작성 · 브리핑 메일 · 텔레그램 알림

실행하고 확인하기

  • Execute workflow → 지금 한 번 실행
  • 메일 한 통 + 텔레그램 하나, 전체 건수·종류별 건수 확인 = 성공
  • 확인 후 활성화 스위치(Active) 켜기 — 켜야 매일 9시 자동 실행

안 될 때

  • 브리핑이 여러 통 날아옴 — 한 건으로 합치기 노드 위치·설정 확인
  • "민원이 없습니다"라고 나옴 — 민원 현황 읽기의 Document·Sheet 확인
  • 프롬프트에 [object Object] — JSON.stringify 누락 확인
  • 텔레그램 메시지가 빔 — 텔레그램 알림이 브리핑 메일 뒤에 붙어있는지 확인, AI 브리핑 작성에서 새로 연결
  • 9시에 안 옴 — 활성화 스위치 및 Timezone(Asia/Seoul) 확인

확인 문제

객관식Q1. Aggregate 노드를 빼면 어떤 문제가 생기나요?

  1. 시트를 읽지 못한다
  2. 민원 건수만큼 AI가 각각 실행되어 메일·텔레그램이 여러 통 발송된다
  3. 스케줄 트리거가 작동하지 않는다
  4. 텔레그램 자격증명이 초기화된다
정답 확인

정답: ② 시트 읽기는 한 줄을 한 건씩 따로 내보내므로, 합치지 않으면 AI가 건수만큼 반복 실행됩니다.

객관식Q2. 텔레그램 알림 노드를 브리핑 메일 노드 뒤에 붙이면 안 되는 이유는?

  1. 속도가 느려져서
  2. 메일 노드를 지나면 값이 발송 결과로 바뀌어 브리핑 글이 사라지기 때문에
  3. 텔레그램은 항상 첫 번째 노드여야 해서
  4. 자격증명이 겹치기 때문에
정답 확인

정답: ② 두 노드 모두 AI 브리핑 작성에서 각각 직접 연결되어야 합니다.

단답형Q3. 이번 워크플로우가 매일 실행되게 하려면 오른쪽 위의 무엇을 켜야 하나요?

정답 확인

정답: 활성화 스위치(Active) — 꺼두면 시각이 되어도 실행되지 않습니다.

이번 프로젝트 워크플로우 받기

따라오다 막혔다면 이 파일을 받아 n8n에서 불러오면 이어서 진행할 수 있습니다.

불러온 뒤 반드시 확인하세요 이 파일에는 자격증명이 들어 있지 않습니다. 불러온 뒤 민원 현황 읽기 · Google Gemini Chat Model · 브리핑 메일 · 텔레그램 알림 네 노드를 각각 열어 자격증명을 다시 골라야 합니다. 그리고 아래 세 자리표시자를 본인 값으로 바꿔야 합니다.

민원 현황 읽기의 Document → 여기에_본인_시트_ID
브리핑 메일의 To → 본인이메일@example.com
텔레그램 알림의 Chat ID → 여기에_본인_chat_id

시트 탭 이름은 시트1로 들어 있으니 본인 시트의 탭 이름이 다르면 목록에서 다시 골라야 합니다. 자격증명과 자리표시자를 고치기 전에는 불러온 워크플로우에 빨간 오류 표시가 납니다 — 고장난 것이 아니라 원래 그렇습니다.
