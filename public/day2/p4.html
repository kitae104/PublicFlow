P4 엑셀 오류 찾기

집행내역 엑셀에 숨은 오류를 워크플로우가 찾아냅니다

왜 이게 필요한가

  • 집행내역·출장 정산·물품 대장처럼 엑셀로 오는 자료를 눈으로 훑어 검토하는 일은 공무원 업무에서 가장 흔한 반복 작업 중 하나
  • 사람의 눈은 줄이 길어질수록 놓치기 쉬움 — 금액이 한도를 넘었는지, 증빙번호가 비었는지는 규칙으로 정해진 확인이라 기계가 훨씬 정확하고 빠름
  • 해결: 엑셀을 폼에 올리면 규칙에 어긋난 건만 골라내고, AI가 담당자에게 보낼 점검 보고서까지 써서 메일로 발송
새로 배우는 것 — 엑셀 파일 읽기(Extract from File)와 조건에 따라 줄 걸러내기(Filter)입니다. 1일차 07강의 IF는 "한 건을 보고 갈래를 나누는" 노드였고, Filter는 "수십 건 중 조건에 맞는 건만 남기는" 노드입니다. P2에서 배운 Aggregate와 P1의 파일 업로드 폼도 그대로 다시 씁니다.
이 실습은 코드가 없습니다 날씨 알리미와 달리 Code 노드를 쓰지 않습니다. "금액이 10만 원을 넘으면 한도 초과" 같은 규칙은 표현식 한 줄로 적습니다.

이번 시간에 만들 것

집행내역 엑셀 한 개를 폼으로 올리면, 규칙에 어긋난 건만 뽑아 AI가 점검 보고서를 쓰고 메일로 보내는 워크플로우를 만듭니다.

점검 규칙은 두 가지입니다.

  • 한도 초과 — 1건 금액이 100,000원을 넘는 건
  • 증빙 누락 — 증빙번호 칸이 비어 있는 건

연습용 엑셀은 가상의 부서 집행내역 45건이고, 오류를 일부러 심어 두었습니다. 몇 건이 나와야 하는지는 실행하고 확인하기에서 공개합니다. 먼저 끝까지 만들어 보고, 워크플로우가 몇 건을 잡아내는지 확인하세요.

연습용 엑셀 내려받기 day2-p4-sample.xlsx
모두 가상 데이터입니다 이름·금액·증빙번호는 연습을 위해 지어낸 값이며 실제 사람이나 기관과 관계가 없습니다. 실제 업무에서 이 워크플로우를 쓸 때는 개인정보가 든 엑셀을 외부 AI에 보내도 되는지를 먼저 확인하세요.

따라하기

  1. 연습용 엑셀 열어보기 위에서 내려받은 day2-p4-sample.xlsx를 엑셀로 엽니다.

    열은 여섯 개입니다 — 사용일 · 부서 · 사용자 · 항목 · 금액 · 증빙번호. 이 첫 줄의 이름이 n8n에서 그대로 항목 이름이 됩니다.

    눈으로 오류를 찾아보고 싶다면 5분만 시도해 보세요. 45줄에서 몇 건이나 찾을 수 있는지 — 그 숫자를 기억해 두었다가 워크플로우 결과와 비교하면 재미있습니다.
  2. 새 워크플로우와 업로드 폼 새 워크플로우를 만들고 이름을 P4 엑셀 오류 찾기로 바꿉니다. 캔버스 가운데 +를 눌러 On form submission을 고릅니다.

    P1과 같은 방법으로 채웁니다.

    Form Title → 집행내역 점검 서비스
    Form Description → 집행내역 엑셀(.xlsx)을 올리면 한도 초과·증빙 누락 건을 AI가 찾아 메일로 보내드립니다.

    Form Elements에서 Add Form Element를 눌러 필드를 하나 만듭니다.

    Label → XLSX
    Element Type → File
    Accepted File Types → .xlsx
    Multiple Files → 끔
    Required Field → 켬

    필드 이름은 영문 XLSX로 지으세요 n8n 폼은 파일 필드의 이름을 그대로 "파일 보관함 이름"으로 씁니다. 한글로 지으면 밑줄(_)로 바뀌어 다음 노드에서 이름을 맞추기 어려워집니다. P1의 PDF와 같은 이유입니다.
  3. 엑셀 읽기 폼 오른쪽 +를 누르고 Extract from File을 고릅니다. Operation을 Extract From XLSX로 바꾸고, Input Binary Field에 XLSX를 적습니다.
    이 노드가 하는 일 엑셀 파일은 "표"로 보이지만 n8n에게는 그냥 파일 덩어리입니다. 이 노드가 파일을 열어 표의 한 줄을 항목 하나로 바꿔 줍니다. 45줄이면 항목 45개가 나옵니다. 1일차에서 구글 시트를 읽을 때와 같은 모양이 됩니다.

    이제 한 번 실행해 봅니다. 이 노드 안의 Execute step 또는 캔버스 아래 Execute workflow를 누르면 폼 화면이 열립니다. day2-p4-sample.xlsx를 올리고 제출하세요.

    OUTPUT 패널에 사용일 · 부서 · 사용자 · 항목 · 금액 · 증빙번호가 줄줄이 보이고, 항목 수가 45로 나오면 성공입니다.

    증빙번호가 없는 줄은 증빙번호 항목이 아예 없는 채로 나옵니다. 값이 빈 칸이 아니라 "항목 자체가 없다"는 점을 기억해 두세요 — 바로 다음 단계에서 이게 쓰입니다.
  4. 줄마다 점검 결과 붙이기 Extract from File 오른쪽 +를 누르고 Edit Fields (Set)를 고릅니다.

    Add Field를 눌러 아래처럼 채웁니다.

    Name → 점검결과
    Type → String
    Value → 표현식 모드로 바꾸고 아래를 붙여넣기 

    {{ !$json.증빙번호 ? '증빙 누락' : ($json.금액 > 100000 ? '한도 초과' : '정상') }}

    아래쪽 Include Other Input Fields를 켜서 원래 열 여섯 개가 사라지지 않게 합니다.

    이 한 줄 읽는 법 조건 ? A : B는 "조건이 맞으면 A, 아니면 B"라는 뜻입니다.
    • !$json.증빙번호 — 증빙번호가 없으면
    • → '증빙 누락'
    • 아니면 $json.금액 > 100000 — 금액이 10만 원을 넘으면 '한도 초과'
    • 그것도 아니면 '정상'
    07강의 IF가 노드로 나누던 일을 한 줄 안에서 하는 셈입니다. 줄이 45개여도 줄마다 한 번씩 알아서 계산합니다.

    다시 실행해 OUTPUT을 보면 모든 줄에 점검결과가 붙어 있습니다. 정상이 대부분이고 한도 초과와 증빙 누락이 섞여 있어야 합니다.

    금액 칸이 글자(문자열)로 읽히면 비교가 어긋납니다. 그럴 때는 엑셀에서 금액 칸을 숫자 서식으로 바꾼 뒤 다시 올려 보세요. 연습용 파일은 이미 숫자입니다.
  5. 오류인 줄만 남기기 오른쪽 +를 누르고 Filter를 고릅니다.

    조건을 하나 만듭니다.

    왼쪽 값 → 표현식 모드로 바꾸고 {{ $json.점검결과 }}
    비교 방식 → String › is not equal to
    오른쪽 값 → 정상

    실행하면 45건이 오류 건만 남습니다. OUTPUT의 항목 수가 몇 건인지 확인하세요.

    Filter와 IF의 차이 IF는 항목을 참 쪽과 거짓 쪽 두 갈래로 나눕니다. Filter는 조건에 맞는 항목만 다음으로 보내고 나머지는 버립니다. "정상은 필요 없고 문제 건만 보면 된다"는 지금 같은 일에는 Filter가 맞습니다.
  6. 한 건으로 합치기 오른쪽 +를 누르고 Aggregate를 고릅니다. P2와 똑같이 설정합니다.

    Aggregate → All Item Data (Into a Single List)
    Put Output in Field → data

    이유도 P2와 같습니다. 오류 건이 아홉 개면 AI 노드가 아홉 번 돌고 메일이 아홉 통 나갑니다. 하나로 묶어서 AI에게 한 번에 넘겨야 합니다.
  7. AI 점검 보고서 오른쪽 +를 누르고 Basic LLM Chain을 고릅니다. 1일차 06강, P1과 같은 방법입니다. Source for Prompt는 Define below로 두고 Prompt 칸을 표현식 모드로 바꿔 아래를 붙여넣습니다. 
    당신은 시청 감사 업무를 돕는 비서입니다.
아래는 지출 집행내역을 점검해 찾아낸 의심 건 목록입니다.

[점검 기준]
- 한도 초과: 1건 금액이 100,000원을 넘는 경우
- 증빙 누락: 증빙번호가 비어 있는 경우

[작성 규칙]
- 맨 첫 줄에 '전체 {{ $('엑셀 읽기').all().length }}건 중 {{ $json.data.length }}건에서 문제가 발견되었습니다.'라고 씁니다.
- 오류 유형별로 나누고, 건마다 사용일·사용자·항목·금액을 한 줄씩 적습니다.
- 마지막에 담당자가 해야 할 조치를 2줄 이내로 제안합니다.
- 목록에 없는 내용은 지어내지 않습니다.

[의심 건 목록]
{{ JSON.stringify($json.data) }}

    이어서 노드 아래의 Model 자리 +를 눌러 Google Gemini Chat Model을 달고, 자격증명을 고른 뒤 Model에서 models/gemini-2.5-flash를 직접 고릅니다. 06강에서 한 것과 같습니다.

    프롬프트 속 표현식 세 개
    • {{ $json.data.length }} — 앞에서 묶은 목록에 든 의심 건의 수
    • {{ $('엑셀 읽기').all().length }} — 엑셀 읽기 노드가 만든 전체 줄 수(45). P3의 $('노드 이름') 문법인데, 한 건이 아니라 전부를 가져오므로 .item 대신 .all()을 씁니다.
    • {{ JSON.stringify($json.data) }} — 의심 건 목록 전체를 글자로 바꿔 AI에게 전달
    "목록에 없는 내용은 지어내지 않습니다"는 AI가 없는 건을 만들어 내는 것을 막으려는 문장입니다. 점검 보고서처럼 숫자와 사실이 중요한 글에서는 꼭 넣으세요.
  8. 점검 메일 보내기 오른쪽 +를 누르고 Gmail을 고릅니다. Send a message를 선택하고 채웁니다.

    To → 본인 이메일 주소
    Subject → 표현식 모드로 [집행내역 점검] {{ $now.toFormat('yyyy-MM-dd') }}
    Email Type → Text
    Message → 표현식 모드로 {{ $json.text }}

    AI가 쓴 보고서는 text라는 이름으로 나옵니다. 06강, P2에서 본 것과 같습니다.
  9. 노드 이름 정리하기 노드 제목을 각각 더블클릭해 아래 이름으로 바꿉니다.

    엑셀 업로드 폼 · 엑셀 읽기 · 점검 결과 표시 · 오류만 남기기 · 한 건으로 합치기 · AI 점검 보고서 · 점검 메일

    엑셀 읽기 이름은 반드시 맞추세요 AI 프롬프트의 $('엑셀 읽기')가 이 이름을 부르고 있습니다. 다른 이름이면 "노드를 찾을 수 없다"는 오류가 납니다.

안 될 때

  • 엑셀 읽기에서 파일을 찾을 수 없다는 오류 — Input Binary Field 값과 폼 필드 이름이 같은지 확인(왼쪽 INPUT 패널에 보이는 이름을 그대로 복사)
  • 항목이 하나도 안 나옴 — 엑셀의 첫 줄이 머리글이어야 합니다. 첫 줄 위에 제목 줄이 있으면 제거하세요
  • 한도 초과가 하나도 안 잡힘 — 금액이 글자로 읽힌 경우입니다. 엑셀에서 숫자 서식으로 바꿔 다시 올리세요
  • 전부 증빙 누락으로 나옴 — 열 이름이 증빙번호와 정확히 같은지 확인(띄어쓰기, 오타)
  • Filter 뒤가 비어 있고 AI 노드가 안 돎 — 오류 건이 0건이면 뒤 노드가 실행되지 않습니다. 정상 동작입니다
  • "노드를 찾을 수 없다" — $('엑셀 읽기')와 실제 노드 제목 일치 확인
  • 메일이 안 옴 — Gmail 자격증명과 받는 주소 확인, 스팸함 확인

  • 중복 결제 찾기 — Summarize 노드로 사용일·사용자·항목·금액이 같은 줄을 묶어 건수를 세고(Count), 건수가 2 이상인 것만 Filter로 남깁니다. 두 쌍이 나오면 성공입니다.
  • 시트에 기록하기 — 오류만 남기기에서 갈래를 하나 더 빼서 1일차 03강처럼 구글 시트 점검결과 탭에 한 줄씩 쌓아 보세요.
  • 한도 바꿔 보기 — 한도를 80,000원으로 낮추면 몇 건이 더 잡힐까요? 점검 결과 표시의 숫자만 고치면 됩니다.

확인 문제

객관식Q1. 엑셀 파일 한 줄을 n8n 항목 하나로 바꿔 주는 노드는?

  1. Edit Fields (Set)
  2. Extract from File
  3. Aggregate
  4. Filter
정답 확인

정답: ② Extract from File이 파일을 열어 표의 줄마다 항목을 만듭니다.

객관식Q2. IF 노드와 Filter 노드의 가장 큰 차이는?

  1. IF는 숫자만, Filter는 글자만 비교한다
  2. IF는 참·거짓 두 갈래로 나누고, Filter는 맞는 것만 남기고 나머지는 버린다
  3. 둘은 똑같다
  4. Filter는 AI와만 함께 쓸 수 있다
정답 확인

정답: ② 문제 건만 필요할 때는 Filter, 두 갈래로 각각 일을 시킬 때는 IF입니다.
