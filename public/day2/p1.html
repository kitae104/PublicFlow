P1 공문서 요약과 기한 등록

PDF를 올리면 요약은 텔레그램으로, 제출 기한은 캘린더로 갑니다

왜 이게 필요한가

  • 아침마다 첨부 공문이 대여섯 건씩 오지만, 대부분 우리 부서와 상관없는 협조 공문이거나 이미 아는 사업의 후속 안내 — 열어보기 전엔 어느 쪽인지 알 수 없음
  • 한 건에 3~5분, 하루 20분이 그저 훑어보는 데 소요됨
  • 더 아픈 문제는 기한을 놓치는 일 — 공문 한 장에 설명회 날짜, 조사 기간, 제출 기한이 뒤섞여 있어서 달력에 옮겨 적다가 틀리거나 아예 잊음
  • 해결: PDF를 올리면 목적·주요 내용·지원 사항·대상·일정 다섯 줄 요약이 몇 초 뒤 텔레그램으로 도착하고, 제출 기한은 캘린더에 자동으로 등록
새로 배우는 것 — AI에게 글을 쓰게 하는 대신 글에서 필요한 값만 뽑게 하는 Information Extractor입니다. 뽑은 날짜는 1일차 05강에서 만든 캘린더 일정 노드에 그대로 넘깁니다.
요약은 판단을 대신하지 않습니다 실제로 처리할 공문은 반드시 원문을 여세요. 목적은 읽지 않는 것이 아니라 "먼저 읽을 것을 고르는 시간"을 줄이는 것입니다.

이번 시간에 만들 것

폼에 PDF 공문서를 올리면 텍스트를 뽑아내 두 갈래로 일을 시키는 독립 프로젝트를 만듭니다. 1일차와 달리 처음부터 새로 만드는 워크플로우입니다.

  • 위 갈래 — AI가 다섯 줄로 요약해 텔레그램으로 보냄
  • 아래 갈래 — AI가 제목·제출 기한·담당부서·필요조치를 뽑아 구글 캘린더에 일정으로 등록
텔레그램 봇과 구글 캘린더 필요 준비물 ② 텔레그램 봇 만들기에서 봇 토큰·chat id 확인. 캘린더는 1일차 05강에서 연결한 것을 그대로 씁니다.

연습용 공문은 가상의 공문 한 장입니다. 날짜가 네 개 들어 있어서 AI가 그중 제출 기한을 제대로 고르는지 확인할 수 있습니다.

연습용 공문 내려받기 day2-p1-sample.pdf
연습용 공문의 날짜는 2026년입니다 수업 날짜보다 이전이어도 캘린더에는 그 날짜 그대로 등록됩니다. 등록 위치를 확인하는 실습이므로 지장이 없습니다.

1일차 결정과 같은 부챗살 구조입니다. 한쪽이 실패해도 다른 쪽은 영향을 받지 않습니다.

따라하기

  1. 새 워크플로우 만들기 이름을 P1 공문서 요약 서비스로
  2. 폼 트리거 추가하기 빈 캔버스 + → 폼 트리거(On form submission)

    Form Title → 공문서 요약 서비스
    Form Description → PDF 공문서를 올리면 AI가 핵심만 요약해 텔레그램으로 보내드립니다.

  3. 파일 업로드 칸 만들기

    Label → PDF
    Element Type → File
    Multiple Files → 끔
    Accepted File Types → .pdf
    Required Field → 켬

    이름은 반드시 PDF 세 글자로 — 한글 이름은 파일 필드명이 밑줄로 깨져 다음 단계에서 알아낼 수 없음
  4. PDF에서 글자 뽑아내기 + → Extract from File → Extract From PDF

    Input Binary Field = PDF(기본값 data 지우고 입력)

    이 노드가 하는 일 — PDF에서 글자만 뽑아 text로 넘김
  5. AI 요약 노드 추가하기 + → Basic LLM Chain

    Source for Prompt → Define below:

    다음 공문서를 5줄 이내로 핵심만 요약하세요.

- 목적
- 주요 내용
- 지원 사항
- 대상
- 일정

각 항목을 한 줄로 정리하세요.
불필요한 설명은 하지 마세요.

[문서 내용]
{{ $json.text }}
  6. Gemini 모델 붙이고 모델 이름 고르기 아래쪽 + → Google Gemini Chat Model → 자격증명 재사용 → models/gemini-2.5-flash 직접 선택
    모델은 이번에도 직접 골라야 함 — preview 모델은 예고 없이 사라질 수 있음
  7. 텔레그램 자격증명 만들기 + → Telegram → Set up credential → Access Token에 BotFather 토큰 붙여넣기

    Resource = Message, Operation = Send Message(기본값 유지)

  8. 받는 사람과 보낼 내용 채우기 Chat ID = 본인 chat id 숫자

    Text 표현식 전환 후:

    📄 공문서 요약

{{ $json.text }}
  9. 여기까지 한 번 실행해 보기 Execute workflow → 연습용 공문(day2-p1-sample.pdf)을 올립니다. 텔레그램에 요약이 오면 위 갈래는 완성입니다. 이어서 같은 공문에서 제출 기한도 뽑아 캘린더에 올립니다. 이미 만든 흐름은 건드리지 않고 갈래만 하나 더 뻗습니다.
  10. 공문에서 기한 뽑아내기 — 두 번째 갈래 PDF 텍스트 추출 노드 오른쪽 끝의 동그란 점을 잡고 빈 곳으로 끌어 놓은 뒤 Information Extractor를 고릅니다. (이미 선이 하나 나가 있어도 새 선을 더 낼 수 있습니다.)

    Text → 표현식 모드로 {{ $json.text }}
    Schema Type → From Attribute Descriptions

    Add Attribute를 눌러 아래 네 개를 만듭니다. Name과 Description을 채웁니다.

    문서제목 → 공문서의 제목 (Required 켬)
    제출기한 → 회신·제출의 마감 날짜를 YYYY-MM-DD 형식으로. 설명회·행사·조사 기간의 날짜와 헷갈리지 말 것. 마감이 없으면 빈 값
    담당부서 → 공문을 보낸 부서 이름
    필요조치 → 받는 기관이 해야 할 일을 한 줄로

    설명이 곧 지시문입니다 AI는 Name이 아니라 Description을 읽고 값을 고릅니다. 공문에는 날짜가 여러 개 나오므로, 제출기한 설명을 "마감 날짜"라고 구체적으로 적고 다른 날짜와 구분하라고 알려 줘야 합니다. 1일차 06강의 프롬프트와 같은 원리입니다.

    아래쪽 Model 자리 +에서 Google Gemini Chat Model을 달고, models/gemini-2.5-flash를 직접 고릅니다. 이 노드의 이름은 자동으로 Google Gemini Chat Model1이 됩니다. 그대로 두세요.

    실행 후 OUTPUT을 보면 output 아래에 네 개 값이 나옵니다. 제출기한이 2026-12-18인지 확인하세요.

    값은 {{ $json.text }}가 아니라 {{ $json.output.제출기한 }}처럼 output을 한 번 거쳐 꺼냅니다.
  11. 제출 기한을 캘린더에 등록하기 기한 추출 오른쪽 + → Google Calendar → Create an event. 1일차 05강의 자격증명을 그대로 고릅니다.

    Calendar → 본인 캘린더 (보통 본인 Gmail 주소)
    Start → 표현식 모드로 아래 

    {{ $json.output.제출기한 + 'T09:00:00' }}

    End → 표현식 모드로 아래

    {{ $json.output.제출기한 + 'T10:00:00' }}

    Add Field로 Summary와 Description을 추가하고 표현식으로 채웁니다.

    [공문 기한] {{ $json.output.문서제목 }}
    담당부서: {{ $json.output.담당부서 }}
필요조치: {{ $json.output.필요조치 }}
    이 식이 하는 일 제출기한은 2026-12-18 같은 날짜 글자입니다. 뒤에 'T09:00:00'(오전 9시)를 붙이면 캘린더가 읽는 날짜·시각 형태가 됩니다. 글자와 글자를 +로 이으면 한 글자열이 됩니다.
  12. 노드 이름 정리하기

    공문서 업로드 폼 · PDF 텍스트 추출 · AI 요약 · 텔레그램 발송 · 기한 추출 · 기한 일정 등록

실행하고 확인하기

  • Execute workflow → 임시 폼 주소로 파일 업로드
  • 제출 후 몇 초 뒤 텔레그램에 📄 공문서 요약 메시지 도착 = 위 갈래 성공
  • 구글 캘린더에 [공문 기한] 2026년 지역 어르신 돌봄 서비스 수요조사 협조 요청 일정이 2026-12-18 오전 9시로 생겼다면 아래 갈래도 성공
함정을 피했나요? 연습용 공문에는 날짜가 네 개 있습니다 — 조사 기간 끝(12월 12일), 사전 설명회(12월 3일), 제출 기한(12월 18일), 활동비 지급(2027년 1월). 일정이 12월 18일에 만들어졌다면 AI가 "제출 기한"이라는 설명을 제대로 읽은 것입니다. 다른 날짜로 만들어졌다면 제출기한의 Description을 더 구체적으로 고쳐 보세요.

폼 위쪽에는 앞에서 적은 제목 공문서 요약 서비스와 설명이 한글로 나오고, 파일 칸 이름만 PDF로 보입니다. 필드 이름을 영문으로 지어도 민원인이 헷갈리지 않는 이유가 이것입니다.

매번 Execute workflow를 누르지 않고 상시로 쓰려면, 오른쪽 위 활성화 스위치(Active)를 켜고 공문서 업로드 폼 노드에 표시되는 상시 주소를 즐겨찾기에 넣어두면 됩니다.

안 될 때

  • 파일을 찾을 수 없다는 오류 — Input Binary Field 값과 폼 필드 이름 확인(왼쪽 INPUT 패널 참고)
  • 요약이 텅 빔 — 스캔본 PDF는 글자 추출 불가, 워드/한글에서 만든 PDF로 재시도
  • 모델을 못 찾는다는 오류 — models/gemini-2.5-flash 직접 선택, 자격증명 확인
  • 텔레그램만 빨간색 — Chat ID 숫자 확인, 봇에게 먼저 말 걸었는지 확인
  • 계속 기다림 — 30초 정도는 정상, 오래 걸리면 멈춘 노드 확인
  • 캘린더에 일정이 안 생김 — 기한 추출 OUTPUT의 제출기한이 2026-12-18처럼 YYYY-MM-DD인지 확인(다른 모양이면 Description에 형식을 다시 강조)
  • 기한이 없는 공문에서 캘린더 노드만 빨간색 — 정상입니다. 마감이 없으면 제출기한이 비어 일정을 만들 수 없지만, 위 갈래(요약)는 이미 끝나 있습니다
  • 기한 추출의 OUTPUT이 비어 있음 — 왼쪽 INPUT에 text가 있는지, Text 칸이 {{ $json.text }}인지 확인

  2. n8n이 한글·특수문자를 밑줄로 바꿔버려 뒤에서 이름을 알아낼 수 없기 때문에
  3. PDF 노드가 영문만 지원해서
