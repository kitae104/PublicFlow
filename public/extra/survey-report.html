Google Form 설문 자동 분석 보고서

설문이 쌓이면 통계와 AI 분석까지 자동으로 메일이 옵니다 — 약 60~90분

왜 이게 필요한가

  • 만족도 조사를 돌리고 나면 늘 같은 순서가 반복됨 — 응답을 다운로드 → 엑셀에서 평균 계산 → 연령대·서비스별로 손으로 집계 → 의견 수십 개를 눈으로 읽고 요약 → 보고서 작성 → 담당자에게 메일
  • 이 중 집계와 서식은 기계가 사람보다 정확하고 빠름 — 사람이 잘하는 건 의견을 읽고 판단하는 일이지, 평균을 손으로 더하는 일이 아님
  • 해결: Google Form으로 설문을 받고, n8n이 매주 금요일마다 스스로 응답을 읽어 통계를 계산하고, Gemini가 서술형 의견을 분석해, 완성된 HTML 보고서를 담당자 메일로 보냄
1일차·2일차에서 배운 것을 그대로 조합합니다 새 노드는 거의 없습니다. Google Sheets 읽기(1일차 3강) · Code 노드(P4) · Basic LLM Chain과 Gemini 모델(1일차 6강) · Gmail 발송(1일차 4강) · 여러 값을 한 곳에 모아두는 Set 노드(1일차 2강)까지, 지금까지 배운 노드를 실제 업무 하나로 이어 붙이는 실습입니다.

이번 시간에 만들 것

아래 순서로 동작하는 자동화를 처음부터 끝까지 만듭니다.

Google Form 작성 → Google Sheets 자동 저장 → (수동 실행 또는 매주 금요일 17시) → n8n이 응답 읽기 → Code 노드가 통계 계산 → Gemini가 의견 분석 → Code 노드가 HTML 보고서 조립 → Gmail로 담당자에게 자동 발송

구글 계정·Gemini API 키 필요 1일차 준비물을 이미 마쳤다면 그대로 재사용합니다. 아직이라면 1일차 준비물의 ① 구글 계정, ② Gemini API 키 항목을 먼저 마치세요.

노드 아홉 개 중 새로 보는 것은 Schedule Trigger가 두 갈래로 Set 하나에 모이는 모양뿐 — 나머지는 전부 배운 노드입니다.

따라하기

  1. Google Form 만들기 https://forms.google.com에서 새 설문지를 만들고, 제목은 민원 서비스 만족도 조사, 설명은 행정 서비스 이용 만족도와 개선 의견을 조사하기 위한 설문입니다. 응답 내용은 서비스 개선을 위한 통계 분석에 활용됩니다.로 입력합니다.

  2. (선택) Apps Script로 Form과 시트를 한 번에 만들기 위 과정을 화면에서 하나씩 클릭하는 대신, 스크립트 한 번 실행으로 Form과 응답용 Google Sheets를 동시에 만들 수도 있습니다. 아래 순서대로 진행합니다.

    script.google.com → 새 프로젝트 → Code.gs에 아래 코드 붙여넣기 → 상단 함수 목록에서 createSurveyForm 선택 → 실행(▷) 버튼 

    function createSurveyForm() {

  const form = FormApp.create('민원 서비스 만족도 조사');

  form.setDescription(
    '행정 서비스 이용 만족도와 개선 의견을 조사하기 위한 설문입니다.\n' +
    '응답 내용은 서비스 개선을 위한 통계 분석에 활용됩니다.'
  );

  form.setConfirmationMessage(
    '설문에 참여해 주셔서 감사합니다.'
  );

  form.addMultipleChoiceItem()
    .setTitle('연령대')
    .setChoiceValues([
      '20대',
      '30대',
      '40대',
      '50대',
      '60대 이상'
    ])
    .setRequired(true);

  form.addListItem()
    .setTitle('이용한 행정 서비스')
    .setChoiceValues([
      '주민등록',
      '복지',
      '세금',
      '교통',
      '기타'
    ])
    .setRequired(true);

  form.addScaleItem()
    .setTitle('전체 만족도')
    .setBounds(1, 5)
    .setLabels('매우 불만족', '매우 만족')
    .setRequired(true);

  form.addScaleItem()
    .setTitle('처리 속도 만족도')
    .setBounds(1, 5)
    .setLabels('매우 불만족', '매우 만족')
    .setRequired(true);

  form.addScaleItem()
    .setTitle('직원 친절도')
    .setBounds(1, 5)
    .setLabels('매우 불만족', '매우 만족')
    .setRequired(true);

  form.addScaleItem()
    .setTitle('다시 이용할 의향')
    .setBounds(1, 5)
    .setLabels('전혀 없음', '매우 높음')
    .setRequired(true);

  form.addParagraphTextItem()
    .setTitle('개선이 필요한 사항')
    .setHelpText(
      '서비스를 이용하면서 불편했던 점이나 개선되었으면 하는 사항을 자유롭게 작성해주세요.'
    )
    .setRequired(false);

  const spreadsheet =
    SpreadsheetApp.create('민원 서비스 만족도 조사 응답');

  form.setDestination(
    FormApp.DestinationType.SPREADSHEET,
    spreadsheet.getId()
  );

  Logger.log('폼 수정 URL');
  Logger.log(form.getEditUrl());

  Logger.log('폼 응답 URL');
  Logger.log(form.getPublishedUrl());

  Logger.log('응답 Spreadsheet URL');
  Logger.log(spreadsheet.getUrl());
}

    실행을 누르면 처음 한 번은 권한 승인 창이 뜹니다. 권한 검토 → 본인 구글 계정 선택 → "Google에서 확인하지 않은 앱" 경고 화면이 보이면 고급 → (프로젝트 이름)(안전하지 않음)으로 이동 → 허용 순서로 진행합니다.

    이 경고는 본인이 방금 작성한 스크립트라서 뜨는 것입니다 구글이 검수하지 않은 개인 스크립트를 실행할 때 항상 나오는 표준 경고 화면입니다. 위 코드를 그대로 붙여넣고 실행한 것이 맞다면 안전하게 허용을 눌러도 됩니다.
    "배포" 버튼은 누르지 않습니다 Apps Script 화면 오른쪽 위의 배포 버튼은 이 스크립트를 웹앱으로 공개할 때 쓰는 기능입니다. 이번 스크립트는 createSurveyForm() 함수를 한 번 실행해 Form과 Spreadsheet를 만들기 위한 것일 뿐, 배포할 필요가 없습니다.

    실행할 때마다 새 Form과 새 Spreadsheet가 만들어집니다. 여러 번 누르면 그만큼 여러 벌이 생기니, 결과를 확인한 뒤 필요 없는 사본은 구글 드라이브에서 지우세요.

    실행이 끝나면 화면 아래 실행 로그에 Form 수정 URL· Form 응답 URL·Spreadsheet URL 세 줄이 찍힙니다. 이 중 Form 응답 URL로 들어가면 방금 만든 설문을 바로 확인할 수 있습니다.

  3. Form 배포하고 테스트해보기 Form 오른쪽 위 미리보기(눈 모양) 아이콘을 눌러 실제 응답자가 보는 화면을 엽니다.

    본인이 직접 테스트 응답을 3~5개 제출합니다. 제출 후 Form 편집 화면의 응답 탭을 누르면 방금 낸 응답이 집계되어 있고, 응답 탭의 초록색 스프레드시트 아이콘을 누르면 연결된 Google Sheets가 열립니다.

    다른 사람에게 받으려면 Form 오른쪽 위 보내기 버튼 → 링크 아이콘에서 URL을 복사해 카카오톡·이메일·문자 등으로 전달하면 됩니다.

  5. 새 워크플로우와 두 트리거 만들기 n8n에서 새 워크플로우를 만들고 이름을 Google Form 설문 자동 분석 보고서로 바꿉니다. 캔버스 가운데 + → Trigger manually로 Manual Trigger를 하나 놓습니다.

    그 아래 빈 공간에 +를 한 번 더 눌러 Schedule Trigger를 따로 추가합니다(P2에서 만든 것과 같은 노드). Trigger Interval = Weeks, Trigger on Weekdays = Friday, Trigger at Hour = 5pm으로 맞춥니다.

    두 트리거를 한 워크플로우에 같이 두는 이유 실습 중에는 매주 금요일까지 기다릴 수 없으니 Manual Trigger로 즉시 실행해 확인하고, 실제 운영에서는 Schedule Trigger가 자동으로 돌립니다. 다음 단계에서 이 둘을 같은 노드 하나로 모읍니다.

    노드 이름을 각각 수동 실행, 매주 금요일 17시로 바꿉니다.

  6. 실습 설정 노드 만들기 — 학생이 고칠 값을 한 곳에 모으기 수동 실행 오른쪽 + → Edit Fields (Set)를 추가하고 이름을 실습 설정으로 바꿉니다. 그다음 매주 금요일 17시 노드의 오른쪽 점에서도 선을 끌어와 같은 실습 설정 노드에 연결합니다 — 수동 실행이든 스케줄이든, 무엇으로 시작하든 이 노드로 모이게 만드는 것입니다.

    Fields to Set에 아래 다섯 개를 문자열(String)로 추가합니다 (reportDays만 숫자(Number)).

    이름타입값(실습용 기본값)의미
    spreadsheetUrlString본인 응답 시트 URLGoogle Form 응답이 저장되는 Google Sheets 주소
    sheetNameString설문지 응답 시트1응답이 쌓이는 시트 탭 이름
    reportEmailString본인 이메일보고서를 받을 담당자 메일 주소
    reportTitleString민원 서비스 만족도 조사 결과보고서 제목
    reportDaysNumber0분석할 기간 — 0은 전체, 7은 최근 7일, 30은 최근 30일

  8. 통계 집계 Code 노드 — 숫자는 여기서만 계산합니다
    이번 실습에서 가장 중요한 설계: 계산은 Code, 해석은 AI Google Sheets에서 받은 원본 데이터를 바로 Gemini에게 던지고 "통계도 네가 알아서 계산해줘"라고 시키지 않습니다. 큰 숫자를 다루는 AI는 종종 평균을 잘못 계산하거나 그럴듯하지만 틀린 숫자를 만들어냅니다(할루시네이션). 그래서 총 응답자 수·평균· 비율처럼 정확해야 하는 숫자는 전부 이 Code 노드가 계산하고, Gemini에게는 "이미 계산이 끝난 확정된 숫자"만 건네 해석과 문장 작성만 맡깁니다.
    응답 데이터 읽기 오른쪽 + → Code. 코드 칸을 전부 지우고 아래를 붙여넣습니다. 
    const days = Number($('실습 설정').first().json.reportDays) || 0;
const cutoff = days > 0 ? Date.now() - days * 24 * 60 * 60 * 1000 : null;

const rows = $input.all()
  .map((item) => item.json)
  .filter((row) => {
    if (!cutoff) return true;
    const ts = new Date(row['타임스탬프']).getTime();
    return !Number.isNaN(ts) && ts >= cutoff;
  });

const total = rows.length;

const avg = (key) => {
  const nums = rows.map((r) => Number(r[key])).filter((n) => !Number.isNaN(n));
  if (nums.length === 0) return 0;
  return Math.round((nums.reduce((a, b) => a + b, 0) / nums.length) * 10) / 10;
};

const countBy = (key) => {
  const counts = {};
  for (const r of rows) {
    const v = r[key] || '미응답';
    counts[v] = (counts[v] || 0) + 1;
  }
  return Object.entries(counts).map(([name, count]) => ({
    name,
    count,
    percent: total > 0 ? Math.round((count / total) * 1000) / 10 : 0,

확인 문제

객관식Q1. 이번 워크플로우에서 총 응답자 수와 평균 만족도를 계산하는 노드는?

  1. Gemini 보고서 분석 (Basic LLM Chain)
  2. 통계 집계 (Code)
  3. Gmail 보고서 발송
  4. 실습 설정 (Set)
정답 확인

정답: ② 정확해야 하는 숫자는 전부 Code 노드가 계산합니다. Gemini는 이미 계산된 숫자를 받아 해석과 문장 작성만 맡습니다.

객관식Q2. 통계 계산을 AI에게 맡기지 않고 Code 노드로 따로 분리하는 가장 중요한 이유는?

  1. Code 노드가 더 예쁜 화면을 보여줘서
  2. AI가 큰 숫자를 다룰 때 틀린 값을 그럴듯하게 만들어낼 수 있어서(할루시네이션)
  3. Gemini는 숫자를 아예 입력받을 수 없어서
  4. Code 노드가 더 빠르게 실행되어서
정답 확인

정답: ② AI는 정확한 계산기가 아닙니다. 확정된 통계는 Code로 계산해 "사실"로 고정하고, AI에게는 그 사실의 해석만 맡겨야 신뢰할 수 있는 보고서가 됩니다.

단답형Q3. 실습을 처음 테스트할 때 실습 설정 노드의 reportDays 값은 얼마로 두는 것이 좋은가요?
