# 화면 캡처 넣는 방법

이 문서 하나만 보고 스크린샷을 찍어 사이트에 올릴 수 있도록 만들었습니다.
HTML을 직접 고칠 필요는 없습니다.

## 요약 (3단계)

1. 스크린샷을 찍는다.
2. 정해진 이름으로 `public/assets/img/` 폴더에 저장한다.
3. 아래 명령을 실행한다.

```
cd "D:/Github/n8n_WS/PublicFlow"
python tools/apply_captures.py
```

끝입니다. 페이지를 열어보면 자리표시자 문구가 사라지고 방금 넣은 이미지가 보입니다.

## 저장 위치

```
D:\Github\n8n_WS\PublicFlow\public\assets\img\
```

이 폴더 하나에만 넣으면 됩니다. 하위 폴더를 만들지 마세요.

## 파일명

**어떤 그림인지는 파일명으로 정해집니다.** 아래 "전체 목록 확인" 명령으로 나오는 `id` 열을 그대로 파일명으로 쓰고, 뒤에 확장자만 붙입니다.

예: `[그림 1-2] 새 워크플로우 만들기`의 id가 `fig-d1-01-2`이면 파일명은

```
fig-d1-01-2.png
```

- id 철자와 대소문자를 그대로 씁니다 (전부 소문자).
- 확장자는 `.png`, `.jpg`, `.jpeg`, `.webp` 중 하나만 됩니다.
- 대문자가 섞여도(`Fig-D1-01-2.PNG`) 일단 인식은 되지만, 실행 결과에 "파일명 대소문자가 규칙과 다릅니다" 경고가 뜹니다. 경고가 뜨면 파일명을 소문자로 바꿔서 다시 저장하세요.
- 어떤 그림의 id가 무엇인지 모르겠으면 아래 "전체 목록 확인" 명령으로 다시 볼 수 있습니다.

## 권장 형식

- 형식: PNG 권장 (스크린샷 도구 기본값이 보통 PNG입니다)
- 크기: 가로 1200~1600px 정도면 충분합니다. 너무 작으면 글자가 안 보이고, 너무 크면 페이지가 무거워집니다.
- **개인정보·API 키·토큰이 화면에 그대로 찍히지 않도록 가리고 찍으세요.** 특히 아래 목록 중 "키 값은 가려서 촬영"이라고 적힌 항목은 반드시 모자이크나 검은 띠로 가린 뒤 저장하세요.

## 넣는 방법

1. 파일을 위 이름 규칙대로 `public/assets/img/`에 저장합니다 (같은 이름이 이미 있으면 덮어씁니다).
2. 아래 명령을 실행합니다.

```
cd "D:/Github/n8n_WS/PublicFlow"
python tools/apply_captures.py
```

3. 실행 결과에 `N개 삽입`이라고 나오면 성공입니다. 브라우저에서 해당 페이지를 열어 확인하세요.

**주의: 반드시 `python`으로 실행하세요. `python3`는 이 컴퓨터에서 아무 일도 하지 않는 껍데기 명령입니다.**

## 다시 찍었을 때 (재촬영)

사진이 마음에 안 들어 다시 찍었다면, **같은 파일명으로 덮어쓰고** 다시 같은 명령을 실행하면 됩니다.

```
python tools/apply_captures.py
```

## 이미지를 지웠을 때 (되돌리기)

이미지 파일을 지우고(또는 다른 곳으로 옮기고) 다시 명령을 실행하면, 그 그림은 자동으로 원래의 "촬영 안내" 문구로 되돌아갑니다. HTML을 손으로 고칠 필요 없이 다시 찍기 전 상태로 돌아갑니다.

```
python tools/apply_captures.py
```

파일명을 그대로 유지하면 이전 이미지를 새 이미지로 갈아끼웁니다. 이미지가 중복으로 쌓이지 않습니다.

## 전체 목록 확인

지금까지 몇 개를 찍었고 몇 개가 남았는지, 어떤 그림들이 있는지 보려면:

```
python tools/apply_captures.py --list
```

**이 명령이 항상 최신 전체 촬영 목록입니다.** 이 문서에는 목록을 표로 따로 옮겨두지
않습니다 — 강의 페이지가 늘어날 때마다 표가 곧바로 낡은 정보가 되기 때문입니다.
필요할 때마다 이 명령을 실행해서 확인하세요.

출력의 각 줄은 다음 순서로 되어 있습니다.

- `id` — 파일명으로 쓸 이름 (예: `fig-d1-01-2`)
- `페이지` — 그 그림이 들어 있는 HTML 파일 경로
- `캡션` — 화면에 보이는 그림 제목 (예: `[그림 1-2] 새 워크플로우 만들기`)
- `촬영 안내` — 무엇을, 어디를 찍어야 하는지 설명
- `상태` — `완료`(이미 이미지가 들어감) 또는 `대기`(아직 찍을 사진)

마지막 줄에는 전체 개수와 완료·대기 개수 합계가 나옵니다.

## 파일명을 잘못 넣었는지 확인

`public/assets/img/`에 넣은 파일 중 어떤 그림에도 해당하지 않는(오타 등) 파일이 있는지 확인하려면:

```
python tools/apply_captures.py --check
```

## 촬영 시 참고사항

- 캡처를 넣어도 "캡처 위치: …" 안내 문구는 사라지지 않습니다. 삽입된 사진 바로 위에 HTML 주석으로 남아서, 나중에 재촬영할 때 무엇을 다시 찍어야 하는지 잊지 않도록 해 줍니다. 화면에는 보이지 않습니다.
- 이미지 하나를 넣을 때마다 사이트 전체가 깨지지 않았는지 확인하려면 다음 명령도 함께 실행하세요.

```
python tools/check_site.py
```

`OK: ...`로 끝나면 정상입니다.

## 규칙

이 프로젝트의 검사 도구가 전제하지만 강제로 막지는 못하는 규칙들입니다. 새 페이지를
쓰거나 기존 페이지를 고칠 때 참고하세요.

- **내부 링크는 항상 `.html` 확장자를 붙입니다.** Vercel의 cleanUrls 기능을 쓰면
  확장자 없는 링크도 배포 후에는 동작하지만, 배포 전까지는 `file://`로 로컬에서
  직접 열어 확인하기 때문에 확장자를 빼면 로컬 미리보기가 깨집니다.
- **`<figure class="capture" id="…">`의 속성 순서는 고정입니다.** `class`가 먼저,
  `id`가 나중입니다. `tools/apply_captures.py`가 이 순서를 그대로 문자열로 찾기
  때문에, 순서가 바뀌면(`id`가 먼저 오는 등) 캡처 도구가 그 figure를 조용히
  건너뜁니다.
- **`.toc`의 오른쪽 라벨(`.d`)은 `flex: none`이라 폭이 줄어들지 않습니다.** 라벨이
  길면 그만큼 행 전체가 넓어져, 좁은 화면에서 가로 스크롤이 생길 수 있습니다.
  강제하는 `max-width`는 없으니 짧게 쓰는 것은 어디까지나 관례입니다. 지금 가장
  긴 라벨은 `공공데이터 API`(9자)입니다 — 이 정도가 참고할 만한 실제 기준입니다.
- **강의 페이지는 영어 n8n UI 문구(`Create Workflow`, `Execute workflow` 등)를
  그대로 씁니다.** 반면 준비물 페이지는 구글·텔레그램처럼 자주 바뀌는 제3자 서비스의
  화면 문구를 일부러 "~와 비슷한 문구" 식으로 얼버무립니다. 강의 페이지의 영어
  문구는 영어판 n8n 화면을 전제로 적어둔 것이므로, 2단계에서 실제 n8n 인스턴스
  화면과 다시 대조해 확인해야 합니다.
